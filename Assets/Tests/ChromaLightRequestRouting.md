ChromaBasicEventRoutingAuditTest contains 59 cases, including the original 28 routes, vanilla/white controls, completed gradients, aliases, null defaults and numeric export preservation. Initial default-Expo and white fixture assumptions were corrected against the published activation gate and configured palette before validation. The active-ring harness was separately corrected and confirmed red before adding ring grouping. ChromaEmptyLightIdEditingTest exercises native empty-ID preservation across shifting and generated gradients, including serialized exports and broadcast isolation.

Native string enums accept quoted numeric values, surrounding whitespace and comma-separated names. Actual JSON numbers remain unsupported native enum inputs and retain CM's existing fallback. SerializedChromaEnumName keeps their raw type on export while caching runtime names during parsing or editing. GLS numeric easing save IDs and ribbon shader IDs retain their separate mappings. Point-data easing flags keep the native `ease` prefix requirement, so event-field numeric aliases do not make numeric point flags active.

Explicit JSONNull enum fields follow the existing nullable export contract and are removed. Raw-type preservation applies to non-null tokens. The standalone ChromaLightGradient(JSONNode) constructor retains its existing named-only validation and has no production caller; beatmap ingestion uses the color constructor and typed serialized easing path.

Existing editor extensions are preserved: TrueHSV, GLS custom color/easing/strobe behavior, V2 AnimateComponent, component repeats, modern underscore reset aliases, and modern legacy RGB/gradient emulation. Published native omission alone is insufficient evidence to remove these routes.

PropID numeric arrays remain qualified: published Chroma accepts an object list but unboxes each item as `int`, whereas its scalar route accepts `long`. Exact published CustomJSONData boxing has not been verified. Ordinary LightID arrays use native numeric conversion and have separate coverage. Shared AnimateTrack/AssignPathAnimation null-history semantics and shipping CustomJSONData V4 attachment are separate contracts and are not established by this inventory.

Native basic-tween Chroma activation recognizes declared Chroma and legacy Chroma Lighting Events requirements/suggestions. A ChromaGLS-only declaration does not establish basic Chroma activation. CM RGB preview without metadata remains an editor extension.

The runtime keeps one sorted color timeline per event type and a sorted actual-boost-change index. Each effect queries these once per frame and retains its existing controller state/tween loop. Native propagation groups are built at initialization or membership rebuild, with active ring discovery and parent lookup outside the frame loop. KamikaziLightArrayTest exercises 4,070 generated lights. No fixed BasicLight lookahead offset is introduced: native callback registration uses aheadTime 0.

Parent validation `TestResults/cli/20261011-213701` passed all 59 basic-routing, four custom-event alias, two ribbon, and three empty-ID editor cases. This establishes the named compiled/runtime routes and ribbon output, rather than fresh gameplay or deployed-player verification.
